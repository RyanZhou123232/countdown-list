# Countdown List Code Review

Reviewed commit `fe2890d` against `SPEC.md`. Verification included code inspection, TypeScript, ESLint in a clean checkout, browser acceptance testing, and a controlled test of simultaneous storage writes. Native Expo Go testing is pending.

## Acceptance criteria

1. **[PASS] Empty state and navigation.** With an empty browser store, the home screen showed **No countdowns yet** and **Add countdown**. Tapping the button opened **New countdown**. The empty state and navigation are implemented in `src/app/index.tsx:66–76` and `src/app/index.tsx:101–108`, and the destination title is configured in `src/app/_layout.tsx:17–18`.
2. **[PASS] Save, return home, and show newest first.** Three consecutive browser saves returned to the home screen. Each entry showed its name and date, and each new entry appeared above the preceding entries. The form awaits the write before navigating in `src/app/add.tsx:30–35`. The storage function prepends the new entry in `src/lib/countdowns.ts:48–56`, and the home screen reloads the list when it regains focus in `src/app/index.tsx:15–28`.
3. **[PASS] Reject a name that is blank or contains only spaces.** With a date entered, saving a spaces-only name showed the name error and left the form open. The early return after trimming also covers an empty name. See `src/app/add.tsx:17–24` and `src/app/add.tsx:73`.
4. **[PASS] Require a date.** With a name entered and the date cleared, saving showed the date validation message and left the form open. The date starts empty and gets checked before the write. See `src/app/add.tsx:11–12` and `src/app/add.tsx:25–34`. The browser and mobile versions use different wording for the same validation.
5. **[PASS] Back navigation discards an unsaved draft.** In the browser, entering both fields and going back returned to the unchanged empty list. The form stores the draft in component state and writes it through the explicit save handler. See `src/app/add.tsx:10–15`, `src/app/add.tsx:30–35`, and `src/app/add.tsx:68–78`.
6. **[PASS] Display calendar-day countdowns.** The browser showed **1 day left**, **Today**, and **1 day ago** for tomorrow, today, and yesterday. The calculation compares day keys at UTC midnight after deriving the current day from the local calendar, which avoids 23-hour and 25-hour daylight saving days affecting the count. See `src/lib/countdowns.ts:8–13`, `src/lib/countdowns.ts:21–24`, and `src/app/index.tsx:78–92`.
7. **[WARN] Expo Go restart still needs device verification.** All three events were present after closing the browser tab and opening a new one. The app uses AsyncStorage and awaits its write before returning home. See `src/lib/countdowns.ts:39–45`, `src/lib/countdowns.ts:48–56`, and `src/app/add.tsx:30–35`. To close this criterion, save a named event in Expo Go, fully quit Expo Go, reopen the project, and verify the event's name and date.

## Additional findings

8. **[FAIL] Overlapping saves can drop an event.** `src/lib/countdowns.ts:48–56` reads the full list, prepends one entry, and writes the full list back. Two calls can read the same old list and both resolve successfully, with the last write replacing the other entry. A controlled test called the real save function twice concurrently with an AsyncStorage test double and confirmed that only one event remained. The form's guard in `src/app/add.tsx:14–18` and `src/app/add.tsx:30–40` applies to a single mounted form. The navigation and date controls remain available during the write. Serialize updates at the storage layer and add an overlapping-save regression check.
9. **[WARN] Invalid stored data can leave the home screen stuck on retry.** If the stored JSON cannot be parsed or contains one invalid record, `src/lib/countdowns.ts:39–45` rejects the entire list. The retry button at `src/app/index.tsx:51–63` repeats the same load and the add button stays hidden while the error persists. Distinguish a transient read error from invalid stored data, and preserve recoverable entries when possible.
10. **[WARN] ESLint flags the retry dependency.** ESLint reported one warning and zero errors. It flags `retry` in the callback dependency array at `src/app/index.tsx:15–28` because the callback never reads it. The dependency deliberately triggers a reload when the retry button increments the value at `src/app/index.tsx:54–59`. Keep that behavior if refactoring the retry path. TypeScript passed.
